# 模块:menu-order(菜单排序)

# ============ 上半部:实现层(实现 agent 用)============

## 职责(一句话)
存储每租户一份「全系统统一的侧边栏顺序」:一级菜单(导航分组)之间、以及同一分组内二级菜单
(叶子菜单 / 二级文件夹)之间的先后顺序。所有用户共享同一顺序(不做按角色/按人个性化)。

## 拥有的实体(写权限唯一归本模块)
- `menu_orders`:每租户唯一一行(软删过滤 + 部分唯一索引),存
  - `group_order` jsonb `string[]` —— 一级菜单(分组)key 顺序,如 `['si','biz','crm',...]`
  - `item_order` jsonb `Record<string,string[]>` —— 每个分组下二级菜单 key 顺序,如 `{ crm: ['lead','opportunity',...] }`

## 实现落点
| 内容 | 文件 |
|---|---|
| 单表 + 每租户唯一索引 | `model.ts`(迁移 `core/db/migrations/0179_menu_orders.sql`) |
| 读 / upsert + 结构校验 | `logic.ts`(`getMenuOrder` / `saveMenuOrder`) |
| 路由 | `routes.ts` |
| 错误码 | `errors.ts`(`INVALID_INPUT`) |
| 权限点 | `permissions.ts`(`menu-order:manage`,归 app-settings 模块) |
| 对外出口 | `api.ts` |
| 前端拖拽面板 | `modules/app-settings/ui/MenuOrderPanel.vue`(系统设置页的一个 tab) |
| 侧边栏按顺序渲染 | `src/App.vue` 的 `groups` computed(读 `apiGetMenuOrder`) |

## 接口
- `GET /api/menu-order` — 无需额外权限(全员登录后读,壳层渲染侧边栏用)。返回 `{ groups, items }`。
- `PUT /api/menu-order` — `menu-order:manage` 守卫,整份覆盖保存 `{ groups, items }`(zod 校验)。

## 权限
- `menu-order:manage`:配置菜单排序(对应系统管理→系统设置→「菜单排序」tab)。GET 读接口全员可用,不设专门权限。

## 核心不变量
- 每租户最多一行(软删部分唯一索引兜底),`saveMenuOrder` 用 upsert 防重复行。
- **排序只重排、绝不隐藏**:前端(App.vue / 面板)按 `[已保存顺序 → 目录原序]` 稳定重排;
  已保存里**缺失**的 key 回落 nav-catalog 原序追加在末尾,已保存里**未知**(目录已删)的 key 忽略。
  ⇒ 核心入口(系统设置等)永远排得进去,不可能被「拖到不可见位置」,排序天然做不到自锁。
- **只排一级 / 二级两层**:二级文件夹(NavFolder)内的三级子菜单不进本表、顺序永远沿用 nav-catalog。
- 后端只兜「结构 / 格式 / 规模」底线(key 形如 `[\w:-]+`、数组、条数上限),**不**校验 key 是否真实存在于
  当前菜单目录 —— 目录随功能开关/权限动态增删,校验会让「目录改了、旧顺序残留已删 key」保存失败。
- 保存时对同层 key **去重保序**(重复 key 取首次位置)。
- 与**功能开关**正交:被关闭的菜单在排序面板仍可见、可排;渲染到侧边栏时再按功能开关规则隐藏/显示。

## 常见改动入口
- 想支持三级排序 → 需扩展 `item_order` 结构 + 面板放开三级 `allow-drag`/`allow-drop`(当前刻意不做)。
- 想按角色/按人个性化 → 需给 `menu_orders` 加维度(当前刻意做成全租户统一)。

# ============ 下半部:需求层(需求 agent 用)============

## 客户会怎么称呼这个模块的事
菜单排序、菜单顺序、调整菜单位置、把某个菜单挪上去/挪下来、左侧导航排序、菜单排列

## 业务概念词典
| 客户会说 | 真实含义 | 对应系统位置 | 代价 |
|---|---|---|---|
| 「把常用菜单排前面」 | 拖拽调整一级/二级菜单顺序 | 系统管理→系统设置→菜单排序 tab | 已具备(轻) |
| 「XX 菜单挪到 YY 上面」 | 同一分组内二级菜单拖拽换位 | 系统设置→菜单排序 tab,拖完点保存 | 已具备(轻) |
| 「把整个财务模块提到最前」 | 一级菜单(分组)之间拖拽换位 | 系统设置→菜单排序 tab | 已具备(轻) |
| 「不同部门看到不同菜单顺序」 | 按角色/部门个性化排序 | 未做(当前全系统统一) | 重 |
| 「把子菜单里的项也排一下」 | 三级(文件夹内子菜单)排序 | 未做(仅一级/二级) | 中 |

## 可调旋钮清单
□ 一级菜单(分组)顺序(轻 · 拖拽,全系统统一)
□ 同一分组内二级菜单顺序(轻 · 拖拽,全系统统一)

## 本模块约定与边界
- 排序**全系统统一**、对所有用户即时生效,不按角色/按人区分。
- 排序**只调顺序、不隐藏菜单**;要隐藏菜单请用「功能开关」tab(feature-toggle 模块)。两者正交:
  被功能开关关掉的菜单在排序面板里仍然看得到、可以排,只是渲染到侧边栏时按开关规则隐藏。
- 只排**一级 / 二级**两层;二级文件夹(如「资金往来」「资料与配置」)里的子菜单不参与排序。
- 核心入口不会因排序而消失(排序不隐藏任何东西)。

## 改动代价速查
- 已具备:拖拽排一级/二级菜单(拖完点「保存顺序」,保存后全系统即时生效,全系统统一)
- 中:放开三级(文件夹内子菜单)排序
- 重:按角色/部门/个人差异化的菜单顺序
